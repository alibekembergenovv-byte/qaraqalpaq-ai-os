## 2024-05-18 - DB Connection Exhaustion and N+1 Optimization
**Learning:** Instantiating `new PrismaClient()` in local scope (like in `src/lib/services/news-collector.ts` and `src/lib/integrations/scheduler.ts`) creates separate database connections, rapidly leading to connection exhaustion in a monolithic Next.js app with hot-reloads. Also, replacing loops of `findUnique` and `create` calls (N+1 queries) with batch `createMany( { skipDuplicates: true } )` drastically improves insertion performance and removes DB bottlenecks, but requires memory-level deduplication inside the batch itself to prevent unique constraint errors *before* data hits the DB.
**Action:** Always import the globally shared Prisma instance from `src/lib/db.ts` instead of calling `new PrismaClient()`. Use `createMany( { skipDuplicates: true } )` with a local `Set` for payload deduplication when inserting batches. Ensure `src/lib/db.ts` correctly assigns the client to `globalThis` in development.
