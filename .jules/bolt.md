## 2024-05-24 - Database Optimization in Background Workers
**Learning:** Background workers (like cron jobs or scrapers) in Next.js can exhaust the database connection pool if they instantiate a new `PrismaClient` locally. In addition, looping over arrays to perform `findUnique` and `create` operations (N+1 queries) severely degrades performance. Batch inserts using `createMany` with `skipDuplicates: true` often fail if there are duplicates *within* the batch payload itself, because Prisma sends the entire payload to the database in one query.
**Action:** Always import the global `prisma` singleton from `@/lib/db` for all services. When inserting a list of items, do application-level deduplication (e.g., using a `Map`) first, then use `createMany({ data, skipDuplicates: true })` to perform O(1) database roundtrips.
