## 2024-05-18 - Prisma createMany Batch Insertion Optimization
**Learning:** When dealing with frequent batch insertions (like ingesting RSS feeds), using Prisma`s `createMany` with `skipDuplicates: true` prevents N+1 query bottlenecks. However, it`s critical to also ensure application-level uniqueness within the batch payload itself (e.g., deduplicating items with a Map) to prevent the entire batch from failing due to duplicate keys within the single insert operation. Another key learning is that the application uses a global singleton Prisma instance in `@/lib/db`, so a new PrismaClient should not be initialized inside individual service files to prevent database connection exhaustion.
**Action:** Replace `findUnique` + `create` loops with `createMany(..., skipDuplicates: true)`, but always pre-deduplicate the batch data before calling the database. Furthermore, always import the Prisma client instance from `@/lib/db` instead of instantiating `new PrismaClient()`.
