## 2023-10-25 - Prevent N+1 issues and Unique Constraint Violations in Bulk RSS Insertion
**Learning:** Batch processing RSS feeds sequentially with `findUnique` and `create` causes major N+1 query bottlenecks and is inefficient for bulk additions. Using Prisma's `createMany` with `skipDuplicates: true` solves this on the database side, however, uniqueness checks must first be applied at the application level (e.g., using a `Map`) because `createMany` will fail if there are duplicates *within* the provided payload itself before it even hits the DB layer.
**Action:** When performing batch data ingestion (such as RSS scraping), process raw payloads using an application-level uniqueness filter (like a Map keyed by URL) and then execute a single Prisma `createMany` operation with `skipDuplicates: true`. Additionally, reuse the global `prisma` singleton from `@/lib/db` to prevent database connection exhaustion, rather than creating localized instances of `PrismaClient`.
