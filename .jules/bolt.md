## 2024-10-28 - [Prisma N+1 and Connection Exhaustion Patterns]
**Learning:** Using `new PrismaClient()` in individual services creates database connection exhaustion. Additionally, iterating over `findUnique` and `create` in RSS scraping loops creates an O(N) query bottleneck (N+1 query problem). However, using `createMany` with `skipDuplicates: true` fails when the *payload itself* contains duplicate URLs (since the DB check processes after the payload generation).
**Action:** Always import the shared Prisma instance from `@/lib/db`. When using `createMany({ skipDuplicates: true })` for batch insertions, use a local `Set` to deduplicate items before passing them to Prisma. Do NOT fetch existing DB records into memory for app-level deduplication as this causes performance regressions and OOM risks; rely on Prisma for DB-level conflicts.
