## 2023-10-26 - Prisma Connection & Batch Insert Optimizations
**Learning:** Instantiating `new PrismaClient()` in individual service files leads to connection exhaustion. Also, when fixing N+1 database queries using Prisma's `createMany({ skipDuplicates: true })`, fetching existing records into memory for app-level deduplication causes performance regressions and OOM risks. However, the batch payload itself MUST be deduplicated in memory (e.g., using a `Set`) prior to insertion, because Prisma will throw an error if the batch payload contains duplicates.
**Action:** Always import the global Prisma singleton (`import { prisma } from "@/lib/db"`). When inserting multiple records, construct the payload, deduplicate the payload internally using a Set or Map, and then let the database handle existing record conflicts via `createMany` with `skipDuplicates: true`.
