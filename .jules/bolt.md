## 2024-05-24 - Batching Prisma Inserts and Next.js Connection Singleton
**Learning:** Using `findUnique` and `create` inside loops for news scrapers causes an N+1 database query bottleneck and can slow down execution significantly. When replacing this with `createMany({ skipDuplicates: true })`, it is crucial to perform application-level deduplication of the batch payload using a `Set` first. Otherwise, duplicate URLs within the same batch can cause the entire batch insertion to fail. Furthermore, instantiating multiple `PrismaClient` instances across different files, or failing to use the global singleton pattern in `src/lib/db.ts`, can easily lead to database connection exhaustion, especially with Next.js fast-refresh during development.
**Action:** Always batch database insert operations using `createMany` combined with `skipDuplicates: true` when dealing with external API loops, and ensure the batch payload is pre-deduplicated in-memory (e.g., using a `Set`). Always use a shared global singleton instance of `PrismaClient` rather than creating new ones per file.
